## 1. 上下集切换

### 功能描述

在氛围灯控制栏右侧提供上一集（◁）和下一集（▷）按钮，支持在多集视频之间快速切换。

### 交互逻辑

| 操作 | 行为 |
|------|------|
| 点击 ◁ | 切换到上一集视频 |
| 点击 ▷ | 切换到下一集视频 |
| 第一集时 ◁ | 按钮置灰，点击无效 |
| 最后一集时 ▷ | 按钮置灰，点击无效 |

### UI 位置

```
💡 ▶  │  ◁  ▷  │  🌙/☀️
氛围灯   上下集    主题切换
```

位于氛围灯控制栏内，与播放器整体风格统一。

## 2. 双击暂停/播放

### 功能描述

双击视频区域可快速切换视频的暂停与播放状态，无需精确点击播放按钮。

### 交互逻辑

| 操作 | 行为 |
|------|------|
| 双击视频区域 | 切换暂停/播放 |
| 单击视频区域 | 呼出/重置控制栏（见第 4 节） |

### 技术实现

使用 ArkUI 的 `TapGesture({ count: 2 })` 绑定在 `ControlOverlay` 上，系统自动识别双击手势，与单击事件互不冲突。

---

## 3. 水平滑动快进快退

### 功能描述

在视频区域水平方向左右滑动，可快速快进或快退视频，最大偏移 30 秒。

### 交互逻辑

| 操作 | 行为 |
|------|------|
| 向右滑动 | 快进（最大 +30 秒） |
| 向左滑动 | 快退（最大 -30 秒） |
| 松手 | 执行 seek，跳转到目标位置 |

### 技术实现

使用 `PanGesture({ direction: PanDirection.Horizontal, distance: 20 })` 绑定在视频 Stack 上，通过 `parallelGesture` 与其他手势共存。滑动距离按比例换算为时间偏移量。

## 4. 控制栏自动隐藏与呼出

### 功能描述

播放视频时，控制栏（播放/暂停、进度条、倍速、全屏等）会在闲置 5 秒后自动隐藏，点击视频区域可重新呼出。

### 交互逻辑

| 场景 | 行为 |
|------|------|
| 播放中 | 控制栏显示 5 秒后自动隐藏 |
| 单击视频区域（控制栏隐藏时） | 呼出控制栏，重新开始 5 秒倒计时 |
| 单击视频区域（控制栏可见时） | 重置 5 秒倒计时，不会立即隐藏 |
| 暂停时 | 控制栏**始终可见**，不会自动隐藏 |
| 恢复播放时 | 重新启动 5 秒自动隐藏倒计时 |

### 设计理念

暂停时保持控制栏可见，方便用户随时操作；播放时自动隐藏，提供沉浸式观影体验。

## 5. 浅色/深色主题切换

### 功能描述

支持一键切换浅色与深色界面风格，所有非视频播放器内部的 UI 控件完整适配双主题。

### 交互逻辑

| 操作 | 行为 |
|------|------|
| 点击 🌙 图标 | 切换到浅色模式 |
| 点击 ☀️ 图标 | 切换到深色模式 |

### UI 位置

主题切换按钮位于氛围灯控制栏最右侧，与上下集按钮同行。

### 适配范围

| 区域 | 深色模式 | 浅色模式 |
|------|----------|----------|
| 页面背景 | `#000000` | `#F5F5F5` |
| 控制栏背景 | `#1A1A1A` | `#FFFFFF` |
| 输入框背景 | `#2A2A2A` | `#F0F0F0` |
| 按钮背景 | `#333333` | `#E8E8E8` |
| 主文字 | `#FFFFFF` | `#1A1A1A` |
| 次要文字 | `#A6A6A6` | `#666666` |
| 禁用文字 | `#555555` | `#AAAAAA` |
| 边框颜色 | `#444444` | `#DDDDDD` |
| 主题色（不变） | `#F67609` | `#F67609` |

### 不适配区域

视频播放器内部（全屏控制栏、进度条、倍速列表等）始终保持深色，与主流视频应用（YouTube、B站）的设计一致。

### 技术实现

- 新增 `ThemeColors` 主题色板类，在构造函数中根据 `isDark` 参数初始化两套颜色
- 通过 ArkUI 的 `@Provide`/`@Consume` 机制在组件树中传递主题状态
- 各组件通过 `this.themeColors.xxx` 引用对应颜色值，自动响应主题切换

## 6. 弹幕系统

### 功能概述

完整的弹幕发送与显示系统，支持用户输入弹幕文本、选择弹幕颜色、实时滚动显示。

### 6.1 弹幕发送

**UI 组件**（位于视频下方弹幕输入区）：

```
[请输入弹幕内容______] [A] [发送]
     输入框          颜色  发送
```

- **输入框**：支持键盘输入，按下回车键或点击发送按钮均可发送弹幕
- **颜色按钮**：显示字母 "A"，使用当前选中的弹幕颜色渲染，点击展开颜色选择面板
- **发送按钮**：橙色胶囊形按钮，点击发送弹幕并自动清空输入框

**发送逻辑**：
1. 获取输入文本，去除首尾空白后判空
2. 自动分配弹幕轨道（共 5 条，轮询分配）
3. 弹幕从视频右侧（90% 位置）开始，向左滚动
4. 创建 `DanmakuItem` 对象追加到弹幕列表

### 6.2 弹幕颜色选择

点击颜色按钮后展开颜色选择面板，提供 **9 种预设颜色**：

| 白色 | 黑色 | 红色 | 黄色 | 蓝色 | 绿色 | 紫色 | 粉色 | 橙色 |
|------|------|------|------|------|------|------|------|------|
| ⚪ | ⚫ | 🔴 | 🟡 | 🔵 | 🟢 | 🟣 | 🩷 | 🟠 |

选中颜色后面板自动关闭，后续发送的弹幕将使用所选颜色。

### 6.3 弹幕显示与动画

**显示层**：
- 弹幕渲染在独立的 `DanmakuOverlay` 层上，位于视频画面之上、控制栏之下
- 使用 `ForEach` 遍历弹幕列表，每条弹幕通过 `margin` 百分比定位
- 设置 `hitTestBehavior(HitTestMode.Transparent)`，确保弹幕不阻挡视频区域的触摸操作

**动画系统**：
- 基于 **delta-time** 的高性能动画，确保不同帧率下移动速度一致
- 刷新频率约 60fps（16ms 间隔）
- 移动速度：每秒移动屏幕宽度的 35%
- 弹幕飞出屏幕左侧后自动从列表中移除，释放资源

**轨道分配**：

```
轨道 1:  top = 8%
轨道 2:  top = 14%
轨道 3:  top = 20%
轨道 4:  top = 26%
轨道 5:  top = 32%
```

通过 `danmakuList.length % 5` 轮询分配，避免弹幕重叠。

### 6.4 数据模型

```typescript
interface DanmakuItem {
  id: string;     // 唯一标识
  text: string;   // 弹幕文本
  color: string;  // 弹幕颜色（十六进制）
  left: number;   // 水平位置（百分比）
  top: number;    // 垂直位置（百分比）
}
```

## 7. 氛围灯系统

### 功能概述

根据视频画面内容实时改变视频四周的灯光颜色，营造沉浸式观影氛围。支持开关控制、颜色预览、双模式颜色提取。

### 7.1 视觉效果

氛围灯在视频区域的**四个方向**渲染柔和的发光效果：

```
    ╔══════ 顶部光晕 ══════╗
    ║                      ║
  左 ║                      ║ 右
  侧 ║      视频画面        ║ 侧
  光 ║                      ║ 光
  晕 ║                      ║ 晕
    ║                      ║
    ╚══════ 底部光晕 ══════╝
```

- 每个方向的光晕使用三段式渐变：`氛围色 → 氛围色(半透明) → 透明`
- 叠加 `blur(15)` 高斯模糊，营造柔和扩散效果
- 普通模式光晕宽度 12vp，全屏模式扩展至 20vp
- 设置 `hitTestBehavior(HitTestMode.Transparent)`，不阻挡触摸操作

### 7.2 布局设计

采用**双层 Stack** 架构：

```
外层 Stack (clip: false)  ← 允许光晕溢出视频边界
  ├── AmbientLightView     ← 氛围灯光晕层 (zIndex: 1)
  └── 内层 Stack (clip: true)  ← 裁剪视频内容
       ├── XComponent       ← 视频播放器 (zIndex: 0)
       ├── DanmakuOverlay   ← 弹幕层 (zIndex: 2)
       ├── ControlOverlay   ← 控制层 (zIndex: 10)
       └── SpeedListOverlay ← 速度列表 (zIndex: 20)
```

外层 `clip(false)` 让光晕自然溢出视频边界，内层 `clip(true)` 确保视频内容不越界。

### 7.3 控制面板

**UI 组件**（位于视频下方控制栏）：

```
💡 ▶  │  当前颜色 🟠
开关 展开  颜色预览
```

- **开关按钮**：灯泡图标 💡，开启时高亮为主题色，关闭时置灰
- **展开按钮**：仅在氛围灯开启时显示，点击展开/收起颜色预览面板
- **颜色预览**：展开后显示 "当前颜色" 文本和实时颜色色块

### 7.4 颜色提取

支持**双模式**颜色提取，自动降级：

**Native 模式**（优先）：
- 调用 C/C++ Native 层 `player.getColorData()` 从视频帧中实时提取颜色
- 提取 6 个方向的颜色：主导色、平均色、顶部、底部、左侧、右侧
- 应用平滑过渡算法（30% 混合因子），避免颜色跳变

**Demo 模式**（降级）：
- 当 Native 层无有效数据时自动启用
- 内置 8 种演示颜色循环：橙、蓝、粉、绿、紫、黄、红、青
- 每 2 秒切换一次颜色，模拟跟随视频内容变化
- 为四个边生成颜色变体（亮度偏移 ±30，色相偏移）

### 7.5 动画系统

- **颜色更新定时器**：按配置间隔（默认 100ms）定期拉取最新颜色数据
- **动画定时器**：16ms 间隔（约 60fps），更新流动偏移量实现光晕呼吸效果
- **流动偏移**：在 `[0, 2π)` 范围内循环，通过正弦函数驱动光晕亮度变化

### 7.6 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| brightness | 0.8 | 光晕亮度（0.0 - 1.0） |
| updateInterval | 100ms | 颜色更新间隔 |
| smoothFactor | 0.3 | 颜色平滑过渡混合因子 |
| flowSpeed | MEDIUM | 流动速度（SLOW/MEDIUM/FAST） |

### 7.7 状态共享

通过 ArkUI 的 `@Provide`/`@Consume` 机制在组件树中共享氛围灯状态：

```
VideoPlayView
  @Provide('ambientLightEnabled')  →  开关状态
      │
      ├── AmbientLightView
      │   @Consume('ambientLightEnabled')  ← 读取开关
      │   @Prop ambientLightColor          ← 读取当前颜色
      │
      └── AmbientLightControlPanel
          @Consume('ambientLightEnabled')  ← 读写开关
          @Prop ambientLightColor          ← 显示颜色预览
```

## 8. 本地上传视频播放

### 功能概述

支持用户从设备本地存储中选择视频文件（MP4、MOV、AVI、MKV 等格式）进行播放，无需依赖应用内置的 rawfile 视频资源。选中的本地视频会显示在选集列表中，可随时切换播放。

### UI 设计

在选集列表末尾添加一个虚线边框的 "+" 按钮：

```
[1] [2] [3] [📁] [+]
           本地视频  上传
```

- **已选本地视频**：以 📁 文件夹图标显示，选中时高亮为橙色边框
- **上传按钮**：虚线边框的 "+" 按钮，点击唤起系统文件选择器

### 交互逻辑

| 操作 | 行为 |
|------|------|
| 点击 "+" 按钮 | 弹出系统文件选择器，过滤 .mp4/.mov/.avi/.mkv 文件 |
| 选中本地视频 | 视频文件添加到列表，自动开始播放 |
| 点击 📁 本地视频项 | 切换到该本地视频播放 |
| 点击 rawfile 视频项（当前在播放本地视频时） | 自动释放 AVPlayer，切回 Native Player 播放 |

### 技术实现

**双播放器架构**：

应用同时维护两套播放器，根据视频来源自动切换：

| 播放器 | 用途 | 视频来源 |
|--------|------|----------|
| Native Player (`libplayer.so`) | 播放应用内置 rawfile 视频 | `resourceManager.RawFileDescriptor` |
| AVPlayer (`media.AVPlayer`) | 播放本地/网络视频 | 本地文件 URI (`file://`) |

**核心流程**：

1. **初始化**：`VideoPlayView` 创建两个 `XComponent`，分别绑定 Native Player 和 AVPlayer 的 Surface
2. **选择文件**：通过 `@kit.CoreFileKit` 的 `DocumentViewPicker` 选择本地视频文件
3. **切换播放**：
   - 播放本地视频时，隐藏 Native Player 的 XComponent，显示 AVPlayer 的 XComponent
   - 切回 rawfile 视频时，释放 AVPlayer 资源，重新初始化，显示 Native Player 的 XComponent
4. **状态同步**：AVPlayer 通过回调同步播放进度、时长、状态到 `VideoPlayViewModel`

**关键类说明**：

| 类/文件 | 职责 |
|---------|------|
| `LocalVideoFile` | 本地视频数据模型，保存文件名和 URI |
| `AVPlayerManager` | 封装系统 `media.AVPlayer`，管理播放生命周期 |
| `VideoPlayViewModel` | 新增 `localVideoFiles`、`isUsingAVPlayer`、`selectLocalVideo()`、`playLocalVideo()`、`switchToNativePlayer()` 等方法 |

### 播放器状态兼容

所有播放控制功能（播放/暂停、快进快退、进度拖动、倍速切换）均同时支持 Native Player 和 AVPlayer：

- `togglePlayPause()`：根据 `isUsingAVPlayer` 标志调用对应播放器
- `performSeek()`：AVPlayer 接收毫秒级时间戳，Native Player 接收秒级时间戳
- `setSpeed()`：AVPlayer 使用 `media.PlaybackSpeed` 枚举，Native Player 直接传数值

## 9. 多端部署（大小屏适配）

### 功能概述

应用支持在手机、平板、2in1 设备上自适应运行，根据窗口宽度自动切换三种布局模式，确保在不同尺寸屏幕上都有良好的观影体验。

### 断点定义

| 断点 | 窗口宽度 | 设备类型 | 布局策略 |
|------|---------|---------|---------|
| sm | < 600vp | 手机竖屏 | 视频占 35% + 下方选集/弹幕区 |
| md | 600-840vp | 手机横屏/小平板 | 视频占 50%，选集紧凑排列 |
| lg | >= 840vp | 平板/大屏 | 左右分栏（左侧视频 60% + 右侧选集 40%） |

### 布局对比

**sm/md 竖屏布局**：

```
┌─────────────────────┐
│                     │
│      视频区域        │  35% (sm) / 50% (md)
│   (弹幕+控制栏叠加)   │
│                     │
├─────────────────────┤
│ 氛围灯控制 + 上下集  │
├─────────────────────┤
│ 弹幕输入区           │
├─────────────────────┤
│ 选集列表 (水平滚动)   │
└─────────────────────┘
```

**lg 大屏左右分栏布局**：

```
┌──────────────────┬──────────────────┐
│                  │                  │
│    视频区域       │   弹幕输入区      │
│ (弹幕+控制栏叠加)  │                  │
│                  │   选集列表 (Grid) │
│                  │                  │
│                  │   氛围灯控制栏    │
│                  │                  │
└──────────────────┴──────────────────┘
        7 : 5 (layoutWeight)
```

### 技术实现

**断点系统**：

- `BreakPointConstants`：定义断点名称和宽度阈值常量
- `BreakPointManager`：监听窗口尺寸变化，计算当前断点并写入 `AppStorage`
- `Index.ets`：通过 `@StorageProp` 读取断点状态，传递给 `VideoPlayView`

**响应式布局**：

`VideoPlayView` 的 `build()` 方法根据断点和全屏状态路由到三种布局 Builder：

```typescript
build() {
  if (this.isFullScreen) {
    this.FullScreenLayout()   // 全屏：所有断点统一
  } else if (this.isLargeScreen) {
    this.LargeScreenLayout()  // lg：左右分栏
  } else {
    this.NormalLayout()       // sm/md：竖屏堆叠
  }
}
```

**大屏适配细节**：

| 元素 | sm/md | lg |
|------|-------|-----|
| 视频标题 | 24fp | 28fp |
| 弹幕输入框 | 160vp | 300vp |
| 选集列表 | 水平 List | 3 列 Grid |
| 播放按钮 | 25vp | 35vp |
| 控制栏高度 | 16% | 12% |
| VideoSelectionView | 固定 35% 高度 | layoutWeight(1) 自适应 |

### 设备支持配置

`module.json5` 中 `deviceTypes` 配置为 `["phone", "tablet", "2in1"]`，使应用可安装到平板和 2in1 设备。

## 10. 自由流转（跨设备接续）

### 功能概述

用户在手机上观看视频时，可将播放任务一键流转到平板或其他 HarmonyOS 设备上继续观看，播放进度、视频索引、倍速等状态完整迁移，实现无缝跨设备体验。

### 流转数据

迁移时携带以下播放状态：

| 字段 | 说明 |
|------|------|
| chooseNumber | 当前播放的视频索引 |
| currentTime | 播放进度（秒） |
| durationTime | 视频总时长 |
| chooseSpeed | 当前倍速 |
| speedText | 倍速显示文本 |
| playState | 播放状态（流转后自动设为暂停，等待用户操作） |
| ambientLightColor | 氛围灯当前颜色 |

### 交互流程

```
手机端（源端）              云端/局域网                平板端（对端）
```

### 技术实现

**module.json5 配置**：

在 `abilities` 中为 `EntryAbility` 添加 `continuable: true`，启用应用接续能力。

**源端数据保存（`EntryAbility.onContinue`）**：

```typescript
onContinue(wantParam: Record<string, Object>): AbilityConstant.OnContinueResult {
  const continueDataStr = AppStorage.get<string>('continueData');
  if (continueDataStr) {
    wantParam['continueData'] = continueDataStr;
    return AbilityConstant.OnContinueResult.AGREE;
  }
  return AbilityConstant.OnContinueResult.AGREE;
}
```

**对端数据恢复（`EntryAbility.onCreate`）**：

```typescript
onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void {
  if (launchParam.launchReason === AbilityConstant.LaunchReason.CONTINUATION) {
    const continueDataStr = want.parameters?.['continueData'] as string;
    AppStorage.setOrCreate('restoreContinueData', continueDataStr);
    this.context.setMissionContinueState(AbilityConstant.ContinueState.ACTIVE);
  }
}
```

**Index.ets 状态恢复**：

```typescript
private async checkAndRestoreContinueData(): Promise<void> {
  const restoreDataStr = AppStorage.get<string>('restoreContinueData');
  if (restoreDataStr) {
    const data: ContinueData = JSON.parse(restoreDataStr);
    // 1. 初始化 ViewModel
    this.viewModel.videoSources = this.videoResources;
    this.viewModel.setUIContext(this.getUIContext());
    await this.viewModel.initialize();
    // 2. 恢复状态
    this.viewModel.restoreFromContinueData(data);
    // 3. 加载视频并 seek
    const newState = await this.viewModel.onVideoSelected(data.chooseNumber, this.videoResources[data.chooseNumber]);
    if (newState !== null) {
      this.viewModel.playState = newState;
      if (data.currentTime > 0) {
        await this.viewModel.performSeek(data.currentTime);
        this.viewModel.playState = this.viewModel.togglePlayPause(this.viewModel.playState); // 暂停
      }
    }
    AppStorage.delete('restoreContinueData');
  }
}
```

**状态序列化/反序列化（`VideoPlayViewModel`）**：

- `serializeContinueData()`：将当前播放状态打包为 `ContinueData` 对象
- `restoreFromContinueData(data)`：从 `ContinueData` 恢复 ViewModel 状态
- 数据通过 JSON 序列化后存入 `AppStorage`，供 `EntryAbility` 在 `onContinue` 时读取

### 注意事项

1. **数据量限制**：`onContinue` 的 `wantParam` 数据需控制在 100KB 以下。当前方案仅传递轻量播放状态（JSON 约 200 字节），远低于限制。
2. **XComponent 重建**：流转到对端后，XComponent 需要重新创建 Surface，Native Player 也需重新初始化。当前方案通过 `onVideoSelected()` 重新创建 Player 来处理。
3. **弹幕不迁移**：为简化实现，弹幕列表不随流转迁移（弹幕是临时 UI 状态，非核心播放数据）。
4. **调试要求**：自由流转功能暂不支持模拟器调试，需要两台真机（同一华为账号、同一 WLAN/蓝牙网络）。
